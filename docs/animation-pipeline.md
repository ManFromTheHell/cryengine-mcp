# Optional animation pipeline (Kimodo and MotionBricks)

Converts motion generated by two NVIDIA models into CRYENGINE `.caf` clips for the Bip01 character rig
used by the GameSDK sample (`sdk_player`). It is optional: nothing else in the repository depends on it.
The conversion is in this repository; the models are not.

| model | role | converted by |
|---|---|---|
| MotionBricks (locomotion, Unitree G1 skeleton) | walking gaits, starts, stops, idle | `animation/motionbricks_*.py` |
| Kimodo (text-to-motion, SOMA 77-joint human skeleton, model `Kimodo-SOMA-RP-v1.1`) | one-shot actions (attack, aim, death, sit, turn and others) | `animation/kimodo_*.py`, `animation/anim_oneshot.py` |

## What is not included

The models, weights, Python packages and generated motion are not in the repository, and nothing here
downloads them. You install and run them yourself under NVIDIA's terms ([NOTICE.md](../NOTICE.md)).
Both run in their own Python environment (MotionBricks needs PyTorch); the conversion scripts
themselves use the project's Python and numpy only. Kimodo conditions on a text embedding from a Llama 3
model, a gated download under Meta's licence; how you provide that encoder is up to your Kimodo install.
Compiling clips needs the engine's `rc.exe`; checking them against the engine needs the editor open.
The tool inputs that are not in the repository: the chosen Kimodo motions (`.npz`, expected in
`anim_sources/kimodo/` under the repository root), the recorded MotionBricks clips, the character's bind
pose (`bridge.character.bindpose` output) and a Crytek locomotion FBX used as a template.

## Stages

1. **Generate** motion with your own Kimodo / MotionBricks install. `animation/motionbricks_record.py`
   (steady gaits) and `animation/motionbricks_scenario.py` (scripted starts, stops, turns) record
   MotionBricks motion headless; they must be run with the MotionBricks environment's interpreter.
2. **Retarget** onto the Bip01 rig (`motionbricks_retarget.py` for the G1 skeleton, `kimodo_retarget.py`
   for SOMA). Limbs are turned by direction, knees and elbows are treated as hinges, pelvis, torso and
   head by frame transfer. No rotation is copied, because the rigs differ in proportion and rest pose.
3. **Cut**: `motionbricks_loop.py` finds a seamless walking cycle; `anim_oneshot.py` cuts a one-shot or
   an in-place loop out of a retargeted motion.
4. **Write** the curves into a copy of a Crytek animation FBX (`motionbricks_fbx.py`, with
   `fbx_binary.py`, a standard-library reader/writer of binary FBX) and **compile** with `rc.exe`
   (`fbx_to_caf.py`).
5. **Check against the engine** without running the game: `anim_sample.py` asks the plugin
   (`bridge.character.samplepose`) for the pose the engine computes from the clip, and
   `motionbricks_validate.py` compares it with what the clip was built to say (default tolerance 3 cm,
   `--tol` to change it; exit code 1 on a miss). `motionbricks_preview.py` draws stick-figure strips of
   recorded motion for a visual check. This checks the engine's pose, not how a clip looks in motion
   in a running game.

## Commands

```
python animation/motionbricks_clip.py <style> <anim name> [--clips <folder>] [--seed N] [--out <folder>] [--no-rc]
python animation/motionbricks_actions.py [name ...] [--no-rc] [--out <folder>]      # start / stop / idle clips
python animation/kimodo_clips.py [name ...] [--no-rc] [--out <folder>]              # rows of CLIPS in the file
python animation/motionbricks_validate.py <name> [--work <folder>] [--samples <samples.json>]
```

Adding a Kimodo clip: put the chosen motion at `anim_sources/kimodo/<src>.npz`, add a row to `CLIPS` in
`animation/kimodo_clips.py` (source file, the prompt and seed it came from, how to cut it, clip kind and
group), run `kimodo_clips.py <name>`, then validate with the editor open. The same prompt and seed give the
same motion only on the same machine and library versions, which is why the chosen motions are kept as
files. `kimodo_clips.py` also writes what a game needs (duration, root travel, the moment of impact for
attacks) into `motionbricks_clips.json`; `examples/ashvale/villager_anim.py` reads it for the Ashvale
example. `tests/test_kimodo_clips.py` is the editor-free self-test of the pipeline; it uses the kept
motions and the manifest, which are not in the repository, so it is not a check you can run from a clean
checkout (not verified).

## Environment variables the modules read

| variable | read by | meaning |
|---|---|---|
| `MOTIONBRICKS_ROOT` | every `motionbricks_*.py` and `kimodo_retarget.py` (through `_paths.MOTIONBRICKS_ROOT`) | root of the MotionBricks install and its recorded clips: `clips/` (recordings, bind pose, SOMA skeleton), `work/`, `repo/motionbricks` and the venv. Default `<repository>/anim_work/motionbricks`. Nothing is downloaded into it; you put the install there or point the variable at it |
| `MOTIONBRICKS_WORK` | `kimodo_clips.py`, `motionbricks_validate.py` | scratch / work folder for clips being built. Default `<MOTIONBRICKS_ROOT>/work` (`--work` overrides it in `motionbricks_validate.py`) |
| `KIMODO_OUT` | `kimodo_clips.py` | where Kimodo wrote candidate `.npz` files, used when a motion is not yet in `anim_sources/kimodo`. Default `<repository>/anim_work/kimodo_out` |
| `CRYENGINE_ENGINE` | `fbx_to_caf.py` | engine folder holding `rc.exe` (default: the Launcher's 5.7.1 LTS install) |
| `CRYENGINE_GAMESDK_DIR` | `anim_inventory.py` | GameSDK sample folder |
| `MANNEQUIN_ADB`, `MANNEQUIN_CONTROLLER`, `MANNEQUIN_CHARACTER` | `mannequin_check.py` | the Mannequin files and character to check (defaults are the Ashvale example's) |

Several command-line defaults also point at a folder named `MotionBricks` on drive C: (`--clips`,
`--out`, `--work`, `--bindpose`, `--skeleton`). Pass the arguments, or set the variables above, for your
own layout.

## Traps worth keeping

- **The locator's first frame.** The engine takes the locator's first frame out of a clip, in position
  and in heading. A locator that does not start at the origin facing zero moves every joint by the
  difference. `anim_oneshot.make_clip` subtracts both, and `motionbricks_validate.py` compares the
  engine's root heading as well. Corpus chunk: `trap-locator-first-frame-position-and-heading`.
- **One animation update per frame.** The animation system updates a character once per frame, so
  sampling a pose twice in the same frame returns the same pose. `anim_sample` steps the clip with no
  real time passing for this reason. Chunk: `trap-animation-sampler-one-update-per-frame`.
- **Hinge limits.** The template FBX has rotation limits on hinge joints (calf, forearm); the FBX SDK
  inside the resource compiler silently clamps anything outside them. Put twist on the thigh or upper
  arm. Chunk: `trap-fbx-rotation-limits-clip-hinge-joints`.
- **MotionBricks idle is a held stance.** Measured: no joint moves more than 1.2 cm in 8 s, and it
  ignores the facing direction, so it cannot turn on the spot. Turn clips come from Kimodo.
- **A speed peak is not always the blow.** An overhead strike's first speed peak can be the weapon going
  up. Look at `motionbricks_preview.py` sheets of every new action; the `peak_after` field of a `CLIPS` row
  skips an early peak.
- **Sampling between key frames** compares a slerp with a linear interpolation of positions: validate on
  whole frames.
- **Reloading Mannequin files in a running editor** after they changed hung and then crashed the editor
  in the author's runs: restart the editor after changing a `.adb` or controller definition, then run
  `mannequin_check` with `reload=false`. Chunk: `trap-mannequin-reload-after-change-crashes-editor`.
- **Script directory on `sys.path`.** A script placed next to a clone of a package of the same name
  imports the clone instead of the installed package; keep your own generation scripts in a separate
  folder from the model's source clone.
