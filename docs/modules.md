# Python modules

Generated by `tools/gen_tools_doc.py` from the `*.py` files in the tool folders and `tools/module_meta.json` (the folder of each module is in `tools/module_folders.json`). Do not edit by hand.

`tools/module_meta.json` records, per module, a one-sentence purpose, a category, whether it needs a running Sandbox editor, and its non-Python dependencies. It comes from a read-through of each file; the modules were not executed to produce it. Names of other modules in this folder are left out of the dependency column; the dependencies shown are external programs, packages, installed engine files or running services.

The modules find each other through `_paths.py`, a bootstrap at the repository root that puts every tool folder on `sys.path`; it is deliberately not listed in the tables below (the generator skips files whose name starts with an underscore). Because of it a script can be started as `python <folder>/<file>.py` from any directory.

## Columns and status values

| Column | Meaning |
|---|---|
| Editor | `yes`: the module needs a running Sandbox editor with the bridge plugin for at least its main function. `no`: it does not. |
| External dependencies | Programs, packages, files or services outside this repository that the module needs. `editor with ClaudeBridgePlugin` means the bridge plugin on its TCP port. |
| Status | `general`: written to work on any project (paths and names may still need configuring). `example / project-specific`: built around the sample game "Ashvale" (its level, NPCs, console commands or assets); read it as an example, it will not run on another project unchanged. `one-off`: a procedure or migration written for a single job. `limited use`: depends on a specific external setup or duplicates another module; see the purpose. |

The Tests group holds both `test_*.py` files and scripts that drive a packaged game or a live editor; the Editor and Status columns tell them apart. The `test_*.py` files in `tests/` are plain scripts that are started directly (for example `python tests/test_knowledge_eval.py`); a test marked `example / project-specific` assumes the Ashvale example project and fails on another project.
